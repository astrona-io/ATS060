# Summary

Reusable workflow resources centralize task or workflow definitions, while each run supplies its own execution inputs and state. Namespaced and cluster-scoped definitions have different lookup and governance boundaries.

References must select the intended resource and template, with compatible arguments. Changes need version and permission review so future runs remain understandable and shared definitions do not become an uncontrolled route to broader execution authority.
